# 🛡️ SpecGuard (스펙가드)

## 1. 서비스 소개

SpecGuard는 외주 개발 회사의 프로젝트 매니저(PM)와 기획 담당자가 고객의 요구사항이 최종 기획서에 빠짐없이 반영되었는지 확인할 수 있도록 지원하는 AI 기반 웹 서비스입니다.

회의록과 메모에서 요구사항을 추출하고, 사용자가 검토한 요구사항을 기준으로 최종 기획서와 비교하여 누락된 항목을 확인하는 것을 목표로 합니다.

## 2. 개발 목적

- 고객과 협의한 요구사항의 누락 방지
- 반복적인 문서 비교 및 검토 업무 부담 감소
- 고객과 개발자 간 의사소통 오류 감소
- 체계적인 요구사항 관리 지원

## 3. 주요 기능

- **회의록 업로드:** 고객과의 회의 내용을 기록한 파일을 등록할 수 있습니다.
- **메모 직접 입력:** 구두로 협의한 내용이나 추가 요구사항을 직접 입력할 수 있습니다.
- **AI 요구사항 추출:** 회의록과 메모에서 고객의 요구사항을 추출합니다.
- **문서·요구사항 검색:** 요구사항 추출 화면에서 모든 회차의 회의록·전사·기획서·추출 결과·AI 초안과 업데이트안을 문자열로 검색합니다. 보관된 이전 버전도 포함하며 범위를 회의록·메모 또는 기획서로 좁힐 수 있습니다.
- **요구사항 수정:** 요구사항의 내용을 사용자가 직접 수정할 수 있습니다.
- **기획서 비교:** 확정된 요구사항과 최종 기획서를 비교합니다.
- **누락 탐지:** 기획서에 반영되지 않거나 변경된 요구사항을 확인합니다.
- **참여 팀원 표시:** 프로젝트 상세에서 소유자와 초대를 수락한 공동 편집자를 확인합니다.
- **계정별 프로젝트:** 사이드바의 워크스페이스 이름을 누르면 내 전체 프로젝트 목록으로 이동합니다.
- **마이페이지 팀 관리:** 소유자가 초대를 보내고, 받은 초대를 수락하며, 팀원을 추방합니다.
- **최근 수정 기록:** 소유자와 공동 편집자의 실제 저장 변경 분야, 저장 시각, 버전을 확인합니다.
- **종 모양 알림:** 정상 저장된 분석·비교 결과와 24시간 뒤의 미해결 누락·충돌 재확인 요청을 사용자별로 보여주고 읽음 상태를 저장합니다.

## 4. 서비스 사용 방법

1. **프로젝트 생성**  
   프로젝트 이름과 고객사 정보를 입력합니다.
2. **자료 등록**  
   고객과의 회의록을 업로드하거나 협의한 내용을 메모로 직접 입력합니다.
3. **AI 요구사항 분석**  
   AI 분석을 실행하여 등록된 자료에서 요구사항을 추출합니다.
4. **요구사항 검토 및 수정**  
   추출된 요구사항을 확인하고 실제 고객의 요청과 일치하도록 수정합니다.
5. **비교 기준 확정**  
   검토한 요구사항 중 최종 기획서에 반영되어야 할 내용을 확정하여 비교 기준으로 사용합니다.
6. **최종 기획서 등록**  
   요구사항과 비교할 최종 기획서를 등록합니다.
7. **비교 실행**  
   확정된 요구사항을 기준으로 최종 기획서를 분석합니다.
8. **결과 확인**  
   요구사항의 반영 여부와 누락 및 변경된 항목을 확인합니다. 분석 결과를 바탕으로 추가 검토가 필요한 내용을 파악합니다.

요구사항 추출 화면 상단의 `문서·요구사항 검색`에 검색어를 입력합니다. `전체`, `회의록·메모`, `기획서` 범위를 선택할 수 있으며, 원문과 근거의 일치 부분·날짜·이전 버전 표식을 확인하고 `전체 내용 보기`로 원문을 펼칠 수 있습니다. 검색은 현재 프로젝트에 불러온 자료만 브라우저에서 비교하는 문자열 검색으로, 입력을 160ms 동안 모아 처리합니다. AI API를 호출하거나 프로젝트 데이터를 수정하지 않습니다. 일치 결과는 처음 20개를 표시하고 `검색 결과 더 보기`로 20개씩 추가합니다.

전체 프로젝트 페이지의 기존 검색은 프로젝트 이름, 고객사, 프로젝트 설명을 대상으로 합니다. 회의록·기획서 전체 문구 검색은 요구사항 추출 화면의 문서 검색을 사용하세요.

## 5. 계정과 데이터 저장

- 프로젝트를 사용하려면 아이디와 비밀번호로 계정을 만들거나 로그인해야 합니다.
- 신규 계정 비밀번호는 7~12자로 설정합니다. 기존에 더 긴 비밀번호로 만든 계정도 계속 로그인할 수 있으며, 비밀번호 원문은 사용자별 salt와 scrypt 해시로만 보관합니다.
- 로그아웃하면 서버 세션과 브라우저 인증 상태를 지우고 `#/`로 이동합니다. 로그인하지 않은 상태에서 마이페이지·프로젝트 관리 경로를 직접 열거나 뒤로 가도 프로젝트 화면은 표시되지 않습니다. 전체 프로젝트 화면에는 대시보드로 돌아가는 링크가 있습니다.
- 마이페이지에서 표시 이름과 소개를 수정하고 저장할 수 있으며, 계정 가입일과 소유·공유 프로젝트 수를 확인할 수 있습니다.
- 계정 정보와 로그인 세션은 `data/users.sqlite`, 프로젝트와 문서·분석 결과는 `data/projects.sqlite`에 저장됩니다.
- 알림과 읽음 상태도 `data/projects.sqlite`에 저장되며, 로그인한 프로젝트 소유자·현재 참여자만 해당 프로젝트 알림을 조회할 수 있습니다. 알림 확인은 앱 로그인 또는 종 모양 알림 목록을 열 때 갱신합니다. 백그라운드 예약 작업이나 이메일·문자·푸시는 사용하지 않습니다.
- 두 SQLite 파일은 앱을 실행할 때 자동으로 생성됩니다. 배포 환경에서는 `data/`를 영구 저장 공간에 연결해야 재시작·재배포 후에도 자료가 유지됩니다.
- 기존 브라우저 프로젝트가 있으면 로그인 후 소유 여부를 확인한 다음 가져올 수 있습니다. 한 번 가져온 브라우저 데이터는 다른 계정으로 다시 복사하지 않으며, 이미 다른 계정에 저장된 프로젝트 ID는 건너뜁니다. 원래 브라우저 데이터는 삭제하지 않습니다.
- 표시 이름과 소개는 마이페이지에서 저장할 수 있습니다. 기존 계정 자료를 유지하면서 `users.sqlite`에 선택 필드로 보관합니다.
- 참여 팀원·초대·수정 기록은 `data/projects.sqlite`의 별도 테이블에 저장됩니다. 기존 프로젝트·계정 자료는 삭제하거나 다시 쓰지 않고, 필요한 선택 필드와 테이블만 추가합니다.

## 6. 마이페이지 팀원 관리와 프로젝트 권한

1. 홈 화면의 `마이페이지` 버튼을 눌러 계정 페이지를 엽니다. 표시 이름과 소개를 수정하고 `프로필 저장`을 누르면 계정 DB에 반영됩니다.
2. 마이페이지에서 `프로젝트 초대 관리`를 누릅니다. `내 프로젝트 팀 관리`에서 프로젝트를 고르고 가입된 아이디로 초대를 보냅니다.
3. 초대 대상은 프로젝트 초대 관리 화면의 `받은 프로젝트 초대`에서 수락합니다. 수락 전에는 참여 팀원으로 표시되지 않고 프로젝트에도 접근할 수 없습니다.
4. 수락된 소유자와 공동 편집자는 프로젝트 상세의 `참여 팀원`에서 확인합니다. 팀원 초대·수락·추방은 프로젝트 초대 관리 화면에서 합니다.
5. 수락한 공동 편집자는 프로젝트 자료를 조회·수정할 수 있습니다. 저장된 변경은 해당 팀원의 로그인 계정 ID로 기록됩니다. 저장된 프로젝트의 AI 분석·비교·음성 전사 요청도 같은 프로젝트 접근 권한을 확인합니다.
6. 프로젝트 소유자만 초대와 추방, 프로젝트 삭제를 할 수 있습니다. 공동 편집자는 다른 팀원을 관리하거나 프로젝트를 삭제할 수 없습니다.
7. 소유자가 팀원을 추방하면 이후 프로젝트·팀원·수정 기록 API 접근이 즉시 차단됩니다. 그 팀원이 이전에 저장한 프로젝트 내용과 수정 기록은 유지되며, 소유자는 계속 확인할 수 있습니다.

## 7. 공개 검토 가이드

로그인하지 않아도 사이드바의 `가이드 보기`를 열어 회의록 등록, 검색, 요구사항 검토·확정, 기획서 비교 방법을 확인할 수 있습니다. 이 안내 화면은 정적 문서이며 개인 프로젝트나 계정 자료를 불러오지 않습니다. 다른 프로젝트·계정 API는 계속 로그인을 요구합니다.

## 8. 수정 기록 기준

- 프로젝트를 새로 만들거나 실제 내용이 바뀌어 저장될 때만 기록합니다. 로그인 세션에서 수정자 ID와 역할을 가져오며, 저장 시각과 버전은 서버가 정합니다.
- 프로젝트 정보, 문서, 요구사항, 검토·확정, 기획서 비교 중 실제로 달라진 분야만 표시합니다.
- 저장과 수정 기록은 SQLite 트랜잭션 하나로 처리합니다. 저장 실패·버전 충돌·내용 변경이 없는 저장은 기록이나 새 버전을 만들지 않습니다.
- 상세 화면에는 최신 5개를 먼저 표시하고, `이전 수정 기록 보기`를 누르면 최대 50개까지 확인할 수 있습니다.
- 새 기록 기능을 적용하기 전의 수정자를 추정하거나 과거 기록을 만들어 넣지 않습니다. 기록이 없는 프로젝트에는 적용 후 실제 저장한 변경부터 표시된다고 안내합니다.
- 기획서 비교가 최신 상태이면 비교 화면 아래의 `기획서 업데이트안 생성`을 눌러 확정 요구사항 기준 제안서를 만들 수 있습니다. 반영 항목은 유지하고, 누락 항목은 추가하며, 충돌 항목은 확정 요구사항에 맞게 수정합니다. 인용 근거는 회의록·전사와 기존 기획서 원문 양쪽에서 공백·줄바꿈·화자 이름을 무시해 확인합니다. 기존 기획서가 없는 프로젝트는 요구사항 추출 화면에서 AI 초안을 생성합니다.

## 9. 알림 동작

- 분석 결과는 프로젝트 저장이 성공한 뒤, 비교 결과는 비교 결과가 프로젝트에 저장된 뒤에만 알림을 생성합니다. 저장 실패나 버전 충돌은 완료 알림을 만들지 않습니다.
- 규칙 기반 비교로 저장된 결과는 알림 내용에 규칙 기반 결과라고 표시하며 AI가 만든 비교 결과라고 표현하지 않습니다.
- 최신 결과의 누락·충돌 재확인 알림은 결과 저장 후 24시간이 지나도 미해결 항목이 남아 있을 때 생성합니다. 삭제·반영 완료 항목과 오래되거나 변경된 분석은 제외합니다.
- 24시간 재확인 알림은 백그라운드 예약 작업이 아닙니다. 로그인 후 알림을 갱신하거나 종 모양 패널을 열 때 기한을 확인해 한 번 생성합니다. 브라우저가 닫혀 있는 동안 전송되지는 않으며 이메일·문자·운영체제 푸시를 보내지 않습니다.
- 알림 패널에서 `전체`·`읽지 않음`을 전환하고 개별 또는 모두 읽음 처리할 수 있습니다. 알림을 누르면 권한이 남아 있는 프로젝트 화면으로 이동합니다.

## 10. 기술 스택

- **Frontend:** HTML, CSS, JavaScript
- **Backend:** Node.js
- **AI Model:** jitda-chat
- **데이터 저장:** SQLite
- **개발 플랫폼:** JITDA(짓다)
- **버전 관리:** Git, GitHub

## 11. 프로젝트 구조

```text
jitda-project/
├── index.html             # 사용자 인터페이스
├── extraction-search.js   # DOM과 분리된 문서·요구사항 문자열 검색
├── server.js              # 서버, 인증·프로젝트 API 및 AI 연동
├── tests/                 # 인증, 저장, 검색, UI 회귀 테스트
├── package.json   # 프로젝트 설정 및 실행 명령어
├── .gitignore     # Git 추적 제외 설정
└── README.md      # 프로젝트 안내 문서
```

실제 실행 후 `data/` 폴더에 `users.sqlite`와 `projects.sqlite`가 생성됩니다. 이 폴더는 Git에 올리지 않도록 제외되어 있습니다.

## 12. 설치 및 실행 방법

### 저장소 복제

```bash
git clone https://github.com/worryjeong/jitda-project.git
cd jitda-project
```

### 환경변수 설정

AI 기능을 사용할 때만 다음 환경변수를 `.env` 파일에 설정합니다. 계정·프로젝트 저장 기능은 API 키 없이 사용할 수 있습니다.

- **LLM_API_KEY:** AI API 인증 키
- **LLM_BASE_URL:** AI API 기본 주소
- **STT_API_KEY:** 음성 전사 API 인증 키 (음성 변환을 사용할 때)
- **PORT:** 서버 실행 포트 (기본값: 3000)

Node.js 22.13 이상이 필요합니다. 서버 실행 시 `.env` 파일이 자동으로 읽힙니다.

### 서버 실행

```bash
npm start
```

### 인증·검색·프로젝트 저장 테스트

```bash
npm test
```
