# 스펙가드

## 서비스 이름과 한 줄 소개

- 서비스 이름: AI 클라이언트 요구사항 누락 탐지기, 스펙가드
- 한 줄 소개: 외주 개발 PM과 기획자가 회의록의 고객 요구사항을 원문 근거와 함께 정리하고, 확정된 요구사항을 최종 기획서와 비교해 누락이나 충돌을 찾도록 돕습니다.

## 해결하는 문제

고객 요구사항은 여러 차례 회의록과 메모에 나뉘어 기록됩니다. 담당자가 이를 기획서와 직접 대조하면 시간이 오래 걸리고, 구두 요청이나 후속 회의에서 바뀐 내용을 놓칠 수 있습니다. 스펙가드는 날짜별 회의 내용과 원문 근거를 모아 보여주고, 기획서에 반영되었는지 확인하는 흐름을 제공합니다.

## 주요 기능

- 프로젝트를 만들고 최근 프로젝트 및 전체 프로젝트 목록에서 검색·열람할 수 있습니다.
- 프로젝트별로 날짜가 있는 회의록·고객 메모를 여러 건 입력하고, 최종 기획서 내용을 입력할 수 있습니다.
- 회의록과 기획서 파일을 업로드할 수 있습니다. 지원 형식은 TXT, MD, PDF, DOCX이며 파일 크기는 최대 10MB입니다.
- LLM이 회의록과 기획서에서 요구사항을 각각 추출하고, 카테고리와 원문 근거를 표시합니다.
- 회의록의 중복 요구사항을 합치고 후속 회의에서 바뀐 요구사항은 최신 문장과 이전 근거를 함께 보여줍니다. 모호한 항목은 “확인 필요”로 표시합니다.
- 요구사항 검토·확정 페이지에서 항목을 수정·확정·삭제하거나 직접 추가할 수 있습니다. 상태 필터, 전체 확정, 근거 확인, 변경 이력도 제공합니다.
- 기획서 비교는 “확정” 상태의 요구사항만 대상으로 합니다. 결과에 반영 여부, 기획서 인용, 회의록 근거와 판단 이유를 표시하고 상태별로 필터링할 수 있습니다.
- 비교 LLM 요청이 실패하면 규칙 기반 결과를 표시하고, 결과와 비교 시각을 저장합니다.
- 프로젝트, 추출 결과, 검토 상태, 비교 결과는 현재 브라우저의 `localStorage`에 저장됩니다. 브라우저나 기기가 다르면 데이터가 자동으로 공유되지는 않습니다.

## 사용 방법

1. 메인 화면에서 “새 프로젝트”를 누르고 프로젝트 이름과 고객사를 입력합니다.
2. 회의별 날짜와 회의록 또는 고객 메모를 입력합니다. 여러 회의가 있다면 “회의록 추가”를 사용합니다. 최종 기획서도 입력하거나 파일로 업로드합니다.
3. “프로젝트 저장”을 누른 뒤 “요구사항 추출” 화면에서 “AI 분석”을 실행합니다.
4. 추출된 요구사항의 문장, 카테고리, 회의 날짜와 원문 근거를 확인하고 “검토·확정으로 이동”을 누릅니다.
5. 요구사항을 수정·확정한 뒤 “기획서 비교”를 누릅니다. 확인 필요·삭제된 항목은 비교 대상에서 제외됩니다.

LLM 결과는 자동 판정이므로 원문 근거를 직접 확인해 주세요. 기획서 인용이 원문에서 확인되지 않으면 “근거 확인 불가”로 표시됩니다.

## 실행 방법

프로젝트 루트에서 Node.js 22 환경으로 실행합니다. 현재 개발 서버 설정과 같이 `.env` 파일에서 환경 변수를 읽으려면:

```bash
node --env-file=.env server.js
```

그다음 브라우저에서 `http://localhost:3000`을 엽니다. 서버는 `PORT` 환경 변수를 사용할 수 있으며, 설정하지 않으면 3000번 포트를 사용합니다.

필요한 환경 변수 이름:

- `LLM_API_KEY`
- `LLM_BASE_URL`
- `PORT` (선택 사항, 기본값 `3000`)

`package.json`의 `start` 스크립트는 `node server.js`입니다. 환경 변수가 이미 셸에 설정된 경우 `npm start`로도 실행할 수 있습니다. 추가 npm 패키지는 사용하지 않습니다.

## 사용 기술

- 화면: HTML, CSS, 브라우저 JavaScript
- 서버: Node.js 내장 `http` 서버와 `fetch`
- LLM: `jitda-chat` 모델을 사용하는 Chat Completions 호환 API, JSON Schema 응답 형식
- 문서 읽기: TXT·MD 직접 읽기, PDF.js(PDF), Mammoth(DOCX)
- 저장: 브라우저 `localStorage` — 서버 데이터베이스는 사용하지 않습니다.

## 팀원과 역할

아래 역할은 6pager에 기록된 담당 범위입니다. 현재 실행 중인 시제품은 Node.js 서버와 브라우저 `localStorage`를 사용하므로, 문서의 FastAPI·DB 계획과 구현 기술 구성이 다를 수 있습니다.

- 강나인 (프론트엔드): 요구사항 조회·수정·확정 화면, 분석 결과와 누락·충돌 근거 표시, 검토부터 기획서 비교까지 테스트 및 화면 개선
- 고민정 (백엔드): FastAPI 구조, 환경 변수·CORS, SQLAlchemy DB 설계, Pydantic 스키마, 프로젝트·요구사항 CRUD API, DB 저장·조회 및 통합 검증
- 손진효 (프론트엔드): 프로젝트 목록·생성·상세 화면, 회의록·메모·기획서 입력 및 업로드 화면, 입력·파일 형식·로딩 상태 처리
- 이민욱 (프롬프트·테스트): 요구사항 추출·비교 프롬프트 설계, 정상·누락·충돌 테스트 데이터 제작, 결과 검증 및 프롬프트 개선
- 라짜코브아리엣 (아리엣, 백엔드): TXT·MD·PDF·DOCX 업로드·텍스트 추출, 문장 분리, LLM 연동, 요구사항 추출·JSON 검증, 원문 근거 매핑 및 기획서 비교
